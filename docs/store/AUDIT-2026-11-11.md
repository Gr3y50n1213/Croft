# Croft store audit (11 November 2026)

Read-only audit of `main`. Web checks were made on 11 November 2026. Two hosts were not reachable from this session (support.google.com, stora.sh), so Play Help pages were confirmed only through search snippets and Google's developer.android.com pages. Those claims are marked "secondary".

## 1. What the build already does right

- **Target API:** `targetSdk = 36`, `minSdk = 26`, `compileSdk = 37` (`android/app/build.gradle.kts`; merged manifest agrees). Play requires API 36 for new apps and updates from 31 Aug 2026 (https://developer.android.com/google/play/requirements/target-sdk, read 11 Nov 2026).
- **Permissions:** none declared (only AndroidX's internal signature permission). Nothing to justify yet.
- **Backup:** `allowBackup="false"`, with `data_extraction_rules.xml` and `backup_rules.xml` excluding every domain from cloud backup and device transfer. Matches the DECISIONS entry that the keystore-bound database cannot be restored elsewhere.
- **No analytics, ads or Firebase:** grep of sources and Gradle found none. The Data safety "nothing collected" answer is true today.
- **16 KB pages:** NDK r29, AGP 9.5.1, `extractNativeLibs=false` in the merged manifest. CI runs `tools/check-16kb-alignment.sh` and `zipalign -c -P 16`. Google's rule: apps targeting API 35+ must support 16 KB pages, and updates that do not cannot be released from 1 Feb 2027 (https://developer.android.com/guide/practices/page-sizes, 11 Nov 2026).
- **Back handling:** only `BackHandler` (the system back-callback API). Android 16 no longer calls `onBackPressed` for apps targeting 36 (https://developer.android.com/about/versions/16/behavior-changes-16, 11 Nov 2026).
- **Edge-to-edge and large screens:** `enableEdgeToEdge()` is called. No orientation, resizability or aspect-ratio locks. Android 16 ignores those on screens of 600 dp or wider anyway (same page).
- **Secrets:** Keystore-wrapped keys in `noBackupFilesDir`, SQLCipher database, a test that no secrets are in sources. Good for the Play and Apple privacy answers.
- **Exported components:** only the launcher activity. The exported `ComponentActivity` and `ProfileInstallReceiver` come from the debug test manifest and AndroidX (the latter is protected by the DUMP permission).

## 3. Rules that will shape T15 to T21

**T15 swipe.** No store rule. Keep TalkBack custom actions as the non-gesture path, and do not exclude the system back-gesture edge.

**T16 queue wiring.** No new permission. Keep error strings free of addresses and secrets (already a project rule).

**T17 onboarding, accounts, sample mailbox.**
- Apple 2.1(a): a built-in demo mode replaces a demo account only with prior approval, and "must exhibit your app's full features". The planned sample mailbox is "read-only", which may fail that test. Make local actions work (move, star, compose into a local outbox) and still provide the real test mailbox in the notes. Use the same notes for Play's App access declaration. Ship the demo mode in all builds so the product behaves the same everywhere.
- Apple 2.1 also rejects placeholder or unfinished content. A disabled "I run a Companion, Coming later" button risks that. Hide it in store builds until the Companion ships.
- Account deletion: adding a mail account is not creating a Croft account. Play's rule covers apps that let people create an account (secondary: https://support.google.com/googleplay/android-developer/answer/13327111, via search results). Apple 5.1.1(v): "If your app supports account creation, you must also offer account deletion within the app". So the Companion registration (S06, S58) must not ship in a Play or App Store build until in-app deletion and a deletion web page exist. Deletion must be real deletion, not deactivation (Play, secondary). Until then, answer "no account" in the Data safety deletion questions.
- Sign in with Apple: not needed. Apple 4.8 exempts "a client for a specific third-party service where users are required to sign in to their mail ... account directly", and apps that use only their own account system. Caution: if the Companion ever offers "Sign in with Google" for the Companion account itself, 4.8 applies.
- Do not make any step depend on push or notifications (Apple 5.1.2(i), 4.5.4).
- Add "Erase all Croft data on this device" to S45 and S60, so the Android and iOS behaviour match.

**T18 conversation and compose.**
- Attachments: use the system document picker and photo picker. Request no storage or `READ_MEDIA_*` permission. Play limits those to apps whose core function needs them (background knowledge, **Confirm**).
- Sharing: FileProvider with a temporary URI grant, never `file://`.
- Intent filters for `mailto:` and `SEND` are exported and BROWSABLE. Declare only what is handled. Android 16 offers opt-in strict intent matching (`intentMatchingFlags`).
- HTML mail: if a WebView is used, turn off JavaScript and file access. Remote content stays blocked by default (Play's unsafe-WebView guidance is background knowledge).
- No `READ_CONTACTS`. Play's contacts policy: broad access only when the Contact Picker is not enough, listed for 27 Jan 2027, with a declaration for apps targeting API 37 (https://developer.android.com/distribute/play-policies, 11 Nov 2026).

**T19 search.** No store rule. Keep the history on the device and out of backup (already so).

**T20 sync and notifications.**
- WorkManager only, no foreground service, no exact alarms. Geofencing leaves the foreground-service list on 27 Jan 2027 (irrelevant here, same page). Whether any type fits IDLE is still **Confirm**.
- Do not use `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`. Play restricts it (background knowledge, **Confirm**). Link to the system battery settings instead.
- `POST_NOTIFICATIONS` is asked after S07 only, and the app works if refused. This matches Apple's rule that apps may not require enabling system features.
- Content-free push payloads are required on iOS (4.5.4). Do the same on the Play flavour. Locally built notifications may show text, but offer a lock-screen privacy option.
- The FCM flavour adds Google libraries: update Data safety (device ID) and check its merged manifest. F-Droid and UnifiedPush builds must not carry them.

**T21 OAuth.** Authorization Code with PKCE through the system browser tab (Android Custom Tabs, iOS web-auth session), never an embedded view. Ship no shared client ID. Tokens only in the keystore. Google's 100-user cap and verification apply only to a shared client. The redirect activity is exported and BROWSABLE, so keep its filter narrow. Apple 4.8 exemption applies (see T17).

**Camera (QR).** Google's on-device scanner needs Play services and breaks F-Droid. Use a bundled decoder and the CAMERA permission, requested at the moment of use.
