# T06: SMTP send and Outbox

Crate / folder: `core/protocols + core/mail-core`

## Goal
Sending, with the undo window and the Outbox screen (S26).

## Spec
- `lettre` (tokio + rustls) with XOAUTH2 support.
- Send writes to the `outbox` table with `send_at = now + undo window`; Undo before `send_at` removes the row; after it the message is sent and then appended to Sent if the server does not do it.
- States: queued, sending, sent, failed with a reason; failed rows can Retry, Edit (returns to a draft) or Discard.

## Done when
- Send with no network queues and sends later exactly once.
- Undo inside the window sends nothing (test on the fake SMTP server).

## Part A: done (branch `task/t06`)

What exists, and the choices behind it. Everything here is tested; see the test names in the files named.

**SMTP adapter** (`core/protocols/src/smtp/`): `SmtpConfig`, `SmtpSecurity` (`Tls` 465, `StartTls` 587, `PlaintextForTestsOnly` for loopback), `SmtpSender::send(envelope_from, recipients, mime) -> Result<SendReceipt, BackendError>`, and `probe_smtp_certificate(&SmtpConfig)` for the account-setup screen (reads the fingerprint to pin, sends nothing secret). It takes the same `Credential` as IMAP: a password is sent with `AUTH PLAIN` (or `LOGIN`), an OAuth credential with `AUTH XOAUTH2`.

- **Why not `lettre`.** lettre 0.11.23 builds its rustls `ClientConfig` itself and takes no custom verifier (only "accept every certificate" or extra roots), so a pinned fingerprint cannot be expressed. `mail-send` 0.7 can take a TLS connector, but it pulls `rustls-platform-verifier` unconditionally, tries CRAM-MD5 and DIGEST-MD5 with the password by default, reads replies without a size limit, and does not tell a failure after the message body from one before it. This module therefore speaks SMTP submission directly over `tokio` and `tokio-rustls` (already dependencies of the IMAP adapter): no new crate, the same TLS policy, bounded replies, hand-mapped errors.
- **Errors.** Connection failure, timeout, a dropped connection or `4xx` before the message is fully sent: `Transient`. `535`/`534`/`530`, any `5xx` to `AUTH`, a server with no usable sign-in method, a certificate or pin that does not verify, a server that hangs up while signing in: `Auth`. Other `5xx`: `Permanent` with a fixed reason (sender, recipient or message refused; too large); never server text or addresses. One refused recipient fails the whole send before `DATA` is issued.
- **The one case that is not retried.** After the final `.` line has been written, a dropped connection, a timeout or an unclear answer means the server may have taken the message. That is `Permanent("May not have been sent; check Sent before retrying")` ([`croft_protocols::smtp::MAYBE_SENT_REASON`]), not `Transient`, so it is never resent automatically. A clear `4xx` after the body is still `Transient` (the server said it did not take it).
- **TLS.** TLS 1.2+, certificate validation always on, a pin only through an explicit fingerprint, `STARTTLS` never falls back to plaintext, bytes that arrive after the `220` to `STARTTLS` are refused, plaintext only for loopback. The verifier code repeats `imap/tls.rs` (that module is private to the IMAP adapter); when both are next touched they should share one implementation.

**Outbox** (`core/mail-core/src/outbox.rs`, `outbox_store.rs`): `Outbox` is the pure state machine; `PersistentOutbox<S: OutboxStore>` keeps it in a store and commits every change before returning. States: `Queued`, `Sending`, `Submitted` (the server accepted it; the copy in Sent is still to be saved), `Filing`, `Sent` (row removed), `Failed`. The Outbox screen lists `Queued`, `Sending` and `Failed` (`OutboxState::shows_in_outbox`).

- The machine holds everything except the message bytes, which live in the store and are read when a message is handed out or taken back. `queue` therefore also takes the envelope (`NewMessage { account, identity, envelope_from, recipients }`): Bcc recipients are not in the headers, and the headers are not parsed to find them.
- Method names: `queue`, `undo`, `take_due` / `take`, `submitted` (the task's `sent`: the server accepted it), `failed`, `take_filing`, `filed`, `filing_failed`, `retry`, `edit_back_to_draft`, `discard`, `recover_after_restart`, `set_offline`, `resume`, `next_wake_ms`, `visible`.
- Back-off and attempt limit are `ops::backoff_ms` and `ops::MAX_ATTEMPTS`. `Transient` retries with back-off (the account's other messages wait too), `Auth` puts the message back in the queue without counting the attempt and pauses the account's outgoing mail, `Permanent` fails with the adapter's reason. Offline hands out nothing and counts no attempt.
- **Never twice.** `take_due` writes `sending` to disk *before* it returns the message. A row found in `sending` after a restart is not sent again: it becomes `Failed` with "May not have been sent; check Sent before retrying" and the person decides (Retry after looking in Sent, Edit, or Discard). This trades a rare manual retry for never sending a message twice. A row found in `filing` goes back to `submitted`, so the copy in Sent is neither forgotten nor causes a resend.
- A failed copy never fails the message: `filing_failed` retries with back-off, pauses on `Auth`, and on a refusal (or after `MAX_ATTEMPTS`) finishes the message with `FilingRejection::GaveUp` so the engine can tell the person once.

**Store** (`core/storage/src/outbox_store.rs`, migration `0004_outbox_append.sql`): the version-1 `outbox` table could hold neither the envelope nor the two states after acceptance, so 0004 rebuilds it (SQLite cannot change a CHECK): adds `envelope_from`, `recipients` (a JSON array, so no address can become two), the states `submitted` and `filing`, and `AUTOINCREMENT` ids (an old Undo button can never act on a newer message). Every statement is scoped by `account_id`. `check_schema.py` and `schema_checks.rs` cover the migration.

**Fake server** (`core/test-support/src/smtp.rs`): `SmtpServer` with EHLO, STARTTLS/implicit TLS, AUTH PLAIN/LOGIN/XOAUTH2, forced replies per stage, per-recipient replies, misbehaviours (accept then drop, hang after data, refused greeting, plaintext injected after STARTTLS, hang up on AUTH), and logs of accepted messages and commands.

## Part B: what the orchestrator must do with this API

Part B wires the Outbox into the engine so that "Send with no network queues and sends later exactly once" runs end to end. In order:

1. **Open it at start.** `PersistentOutbox::open(SqliteOutboxStore::new(db))`. `SqliteOutboxStore<D>` takes anything that lends a `&mut Db`; if the op queue already owns the engine's `Db`, open a second `Db` on the same file for the Outbox (WAL allows it, and migrations are idempotent). Read `recovered_after_restart()`: each id is a message that was being sent when the app stopped; show one notification per id with the row's `last_error` ("May not have been sent; check Sent before retrying").
2. **Mirror the account state.** Wherever the engine calls `OpQueue::set_offline(account, x)` also call `PersistentOutbox::set_offline(account, x)`; wherever it resumes an account after the person signed in again, call `resume(account)`. When `failed(..)` returns `SendRejection::AccountNeedsAttention` (or `filing_failed` returns `FilingRejection::AccountNeedsAttention`), pause the op queue for the same account too: they share one credential.
3. **Send intent.** The composer builds the MIME text and the envelope: `envelope_from` is the identity's address, `recipients` is To + Cc + Bcc as bare addresses. **The stored MIME must not contain a `Bcc:` header**: `SmtpSender` sends the bytes as stored. Call `queue(NewMessage { account, identity, envelope_from, recipients }, mime, now_ms, undo_window_ms)` (the window is the S49 "undo send time") and give the returned `OutboxId` to the "Sending... Undo" snackbar. Undo calls `undo(id, now_ms)`: on `Ok(RemovedMessage)` reopen the composer with `mime`; `Err(OutboxError::Undo(TooLate))` means the window closed. Nothing reaches the server before `send_at`.
4. **The send loop.** Wake at `outbox().next_wake_ms()` and on every connectivity or sign-in change. For each `DueMessage` from `take_due(now_ms, limit)` (already marked `sending` on disk): build `SmtpSender::new(config, credential)` with a fresh credential (refresh an OAuth token first) and call `send(&entry.envelope_from, &entry.recipients, &mime)`. `Ok` -> `submitted(id, now_ms)`. `Err(e)` -> `failed(id, &e, now_ms)` and act on the `SendRejection`: `RetryAt(t)` -> schedule a wake, `Failed` -> notify once with `entry.last_error`, `AccountNeedsAttention` -> sign-in prompt. Never drop an in-flight `send` future: if the app is killed or the future cancelled after the final dot, the row stays `sending` and is failed as "may not have been sent" at the next start. On shutdown, wait for in-flight sends, and on Android run the loop in a job that is allowed to finish.
5. **Filing the copy in Sent.** Right after `submitted`: if the account's server files Sent itself (Gmail), call `filed(id)`. Otherwise call `take_filing(now_ms, limit)` and, for each `DueMessage`: look the Message-ID up with `find_by_message_id(sent_folder, id)` first (a crash in the middle of an append may already have saved it), and if it is absent `ImapBackend::append_message(sent_folder, &["\\Seen"], text)`; then `filed(id)`, or on error `filing_failed(id, &e, now_ms)` (on `GaveUp` tell the person once: "Sent, but couldn't save a copy"). The Sent folder is the one with `SpecialUse::Sent`; if there is none, `create_folder("Sent")`. Note `append_message` takes `&str`, so the MIME must be valid UTF-8 (the composer should produce 7-bit or UTF-8 MIME); if 8-bit non-UTF-8 text must be supported, `append_message` needs a bytes variant (an IMAP-adapter change, outside T06).
6. **Outbox screen (S26).** `outbox().visible(account)` lists Queued, Sending and Failed rows. Retry: `retry(id, now_ms)`; before it, if `entry.may_have_been_sent()`, ask the person to check Sent first. Edit: `edit_back_to_draft(id)` returns `RemovedMessage { entry, mime }` for the composer. Discard: `discard(id)`, with the confirmation. `Sending` rows cannot be edited or discarded (`OutboxError::Action(WrongState)`).
7. **End-to-end tests to write in the engine crate** (use `croft_test_support::SmtpServer`): offline `queue` -> advance time -> `accepted()` is empty -> back online -> exactly one accepted message -> advance time again -> still one. Undo inside the window -> `accepted()` empty after any amount of time. Kill after `take_due` (drop the engine) -> reopen -> the row is Failed and `accepted()` stays at whatever it was. `SmtpMisbehavior::AcceptThenDrop` -> the row fails with "May not have been sent" and is not resent.

## Part B: done (branch `task/t06b`)

The Outbox is wired into the engine (`core/engine`), and the sending interface is in `core/protocols/src/submit.rs`. The seven steps above were followed; this records the choices.

**Interface.** `MailSubmitter` (`send`, `files_sent_itself`, `file_in_sent`) is separate from `MailBackend`, so JMAP can implement it with `EmailSubmission/set` without touching the IMAP trait. `SmtpImapSubmitter { smtp, imap: Arc<ImapBackend>, files_sent_itself }` is the SMTP and IMAP one. `file_in_sent` lists the folders, takes the one marked Sent (creates "Sent" if none), looks the Message-ID up and appends with `\Seen` only if it is absent. Limit: `append_message` takes `&str`, so a MIME that is not valid UTF-8 gives `Permanent` ("needs a message in UTF-8 or 7-bit text") and the copy is given up (the message itself was sent). To change this, the IMAP adapter needs a bytes variant. `SmtpSender::send` was not `Send` (a `Cell` held across an `.await`); it is now an `AtomicBool`, with no change in behaviour.

**Engine.** `Engine::open_with_outbox(db, outbox_db, clock, config)`; `Engine::open` is unchanged and has no Outbox. `add_account_with_submitter` / `attach_account_with_submitter` (the old `add_account` / `attach_account` still work and cannot send). `EngineHandle`: `send(NewMessage, mime) -> Result<OutboxId, SendError>` (window from `set_undo_window_ms`, the S49 "undo time"), `undo_send`, `outbox`, `retry_send`, `edit_back_to_draft`, `discard_send`. `Change` gained `Outbox`, `SendFailed` and `NotFiled` (the copy was given up: the Outbox row is gone, so the screen needs its own notice). `EngineError::NoOutbox` was added.

**One Db or two (decision).** A second `Db` on the same file, behind its own `Mutex`. The queue owns the first `Db` through its store, and `SqliteOutboxStore` needs a `&mut Db` for every call, so one `Db` cannot serve both without a lock around the whole database that the screens' reads would also take. Two connections are fine under WAL (each write is a short immediate transaction, the busy timeout is 5 s), the two locks are never held together, and a large MIME written when queueing does not block the queue. Cost: the caller opens the file twice (same path and key), and an in-memory database cannot be used (the second connection would be a different database without the account rows).

**Account state.** `set_online` and `signed_in` mirror to the Outbox (`set_offline`, `resume`). A refused sign-in while sending does not call a pause on the op queue (it has no such call); it sets the engine's `needs_sign_in` flag and emits `SignInNeeded`, and a cycle does nothing while that flag is set, so queue, syncs and Outbox all stop until `signed_in`. The Outbox's own pause is set by `failed` and cleared by `signed_in`.

**The send loop.** Inside the account cycle, after the due operations and before a sync: send everything due (one at a time), then save copies. The lock is never held across an `.await`. Two details that are not in the Outbox API:

- `PersistentOutbox::take_due` and `take_filing` hand out the messages of **all** accounts. The engine switches every other account's mail "offline" in memory for the length of one take (under the Outbox lock), so an account's task only ever receives its own messages. Test: `one_accounts_run_never_sends_another_accounts_mail`. A per-account take in `mail-core` would be cleaner.
- The task's sleep needs a per-account wake time; `Outbox::next_wake_ms` covers all accounts and has the holds inside it. The engine computes it from the account's own entries plus the holds it saw in `failed` / `filing_failed` (`RetryAt`), so a task never wakes at a time where nothing can be handed out (that would spin).

**Never dropping a send.** The send is awaited in the account task. `Engine::shutdown` and `remove_account` keep waiting past `shutdown_grace_ms` while a send is in flight (the SMTP sender's deadline, 120 s by default, ends it). If the future is dropped anyway (a `run_once` caller gives up, a test aborts the task), a guard calls `abandon`, so the row becomes Failed "may not have been sent" at once instead of staying Sending until the next start; a copy that was being saved goes back to wait (`filing_failed`, `Transient`). A commit failure after the server answered does the same.

**Announced once.** Rows that were Sending at open are Failed with the "may not have been sent" reason, and each gets one `Change::SendFailed` when its account is added; subscribe before adding accounts. The Outbox list shows them whenever the screen is opened.

**Not done / limits.**
- A message with no Message-ID is filed without the look-up (the composer must always write one). The engine does not add one.
- The credential in a `SmtpImapSubmitter` is fixed at construction. After `signed_in` with a new password or token, the caller must build a new submitter (the engine has no call to replace one yet), so an OAuth refresh is not handled here.
- A `Failed` row from "gave up after 8 tries" is announced with `SendFailed` like the others.
- Not tested: the creation of a Sent folder (the in-process IMAP server always has one). Covered only by `pick_sent`'s unit tests.
- `croft_test_support::TestServer` and `SmtpServer` read lines as text, so no test sends a non-UTF-8 message.

**Tests** (`core/engine/tests/outbox.rs`, end to end with `SmtpServer` and the in-process IMAP server): offline send (once), Undo inside and after the window, `Bcc:` refused (also folded, mixed case), kill while the server holds the message (reopen: Failed, announced once, not resent), a cancelled send future, `AcceptThenDrop`, filing exactly once, a crash after the append and a crash before it, `files_sent_itself`, a refused sign-in stopping queue and Outbox then `signed_in`, temporary failure with back-off, Failed -> Edit / Retry / Discard, a copy given up with one notice, two accounts, and the account task waking itself at the end of the window (system clock, 400 ms window).
